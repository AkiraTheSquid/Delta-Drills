# reference

## Purpose
The control in the experiment. A page that renders OUR notebook content under
THEIR measured design, so the harness has something to validate itself against:
if `diff.py lw mockup` reports the prose and headings as matching, the
measurements are trustworthy, and any difference `diff.py mockup ours` then
reports is really ours.

## Owns
- `mockup.html` / `mockup.js` / `mockup.css` — the reference rendering.
- The page-level design values read out of ForumMagnum's rendered post and
  re-typed here: the type scale, the 682px column, the light palette.

## Does NOT own
- Their code. ForumMagnum is GPL-3.0. It is cloned OUTSIDE this repo and read in
  place; nothing under this folder is copied from it.
- 🔴 **The rail. Not its CSS, not its markup, not one class of it.** This page
  LINKS the app's `styles/practice/arena-notebook-nav.css` and mounts the app's
  `ArenaNotebookNav`; `mockup.css` only maps the app's token names onto this
  page's light palette. Until 2026-09-02 it kept its own copy, and that copy
  went stale the moment the app's rail was restructured — so every comparison
  taken through this page in between was measuring a design nobody shipped.
  `watch.py` fails if `.anb-toc-row` or `.anb-toc-dot` reappears in either file.
- `lw-toc.html` / `lw-toc.css` / `ours-toc.html` / `ours-toc.css` — generated by
  `dom_clone.py`, gitignored, overwritten on every run. Do not edit them.

## Key Files
- `mockup.html`: the page. Loads a notebook by `?nb=<slug>` (default `arena-0-1`).
- `mockup.js`: fetches `Local_Deployed_Shared/lessons/notebooks/<slug>.json`,
  renders it with the app's own `LessonGate.renderMarkdown` when it can load it
  and a small fallback renderer when it cannot, then MOUNTS the app's rail.
- `mockup.css`: their page design — the type scale, the 682px column, the light
  palette — plus the token aliases the app's rail stylesheet reads.

## Data & External Dependencies
- The compiled ARENA notebooks under `Local_Deployed_Shared/lessons/notebooks/`.
- `practice/config.js` + `practice/lessons.js`, for the real markdown renderer.
- Served over the same :5175 static server as the app; opening the file directly
  will not work, because it fetches.

## How It Works (Flow)
1. `mockup.html?nb=arena-0-1` fetches that notebook's JSON.
2. Cells render into a 682px column; headings become rail rows.
3. `ArenaNotebookNav.mount()` — the app's own module — builds the rail over
   those headings, exactly as it does in the product.
4. `capture.py mockup` measures it exactly as it measures the live post.

## Invariants & Constraints
- 🔴 IT USES OUR CLASS NAMES (`anb-toc-row`, `nbv-md`, ...). That is the whole
  point: one role map in `targets.json` then serves both the mockup and the app,
  and a difference between them is a difference in VALUES, not in markup.
- 🔴 THE VALUES COME FROM THEIR SOURCE, NOT FROM THEIR PIXELS. The first version
  of the rail here was measured off a screenshot and got the shape wrong — a
  3x2px dash per section instead of their bullet character on a rule.
  `source_diff.py` is what keeps the app honest about this; the mockup is kept in
  step by hand.
- Renderer differences are not design findings: `window.__mockup.renderer` says
  whether the real renderer or the fallback drew the page.

## Extension Points
- A different notebook: `?nb=<slug>`.
- A new design value to hold: add it here AND to the app's stylesheet, then add
  the pair to `source_diff.py`'s `MAP` so it is checked from then on.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **The mockup drifts from the app** — `ACTIVE`
  - When it happens: the app's rail is fixed and the reference is not.
  - Symptom: `diff.py mockup ours` reports differences that are really the
    mockup being out of date, and the real regression hides among them.
  - Root cause: two files carrying the same intention with no link between them.
  - Prevention/fix: `source_diff.py` compares the APP against their source; when
    it comes back clean and `mockup` still differs, the mockup is what is wrong.

- **Labels pile on top of one another when the rail opens** — `RESOLVED`
  - Root cause: `min-height` is a flex item's SHRINK FLOOR. 9px is right for a
    lone dot and lets forty labels overlap the moment they fade in.
  - Prevention/fix: `min-height: auto` while open, which puts the floor back at
    the row's content and hands over to the scroller.
