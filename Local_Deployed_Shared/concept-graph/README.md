# concept-graph/

## Purpose

Front-end assets for **visualising the atom-level concept graph** — the ~205 skills ("atoms") and the prerequisite / encompassing links between them. This folder owns how that graph is *drawn and explored in the browser*; it does not own how the graph is *derived* (that lives in `This-Directory-Only/scripts/` and `This-Directory-Only/backend/`).

## Owns

- The interactive graph embeds shown to users/reviewers.
- The exported, browser-ready graph data (`graph-viz.json`).
- Client-side readiness/prereq helper data consumed by the viz and practice UI.

## Does NOT own

- **Deriving** the graph (edges, tiers, encompassing links) — owned by `This-Directory-Only/scripts/export_graph_viz.py` and the backend `concept_graph.py` / edge-packet pipeline. `graph-viz.json` is a generated artifact; edit the exporter, not the JSON by hand.
- Which problem Practice picks next — that walks the graph but lives in `practice/`.

## Key Files

- **`graph-viz.json`** — exported graph: `{ nodes:[{id,label,topic,family,tier}], edges:[{source,target,enc}] }`. `source → target` means *source is a prerequisite of target*. `enc:true` = encompassing (credit-flow) link; `enc:false` = structural prerequisite. Generated by `export_graph_viz.py`.
- **`graph-viz.js`** — Cytoscape.js embed for the **Knowledge Graph tab** in the main app (`index.html`, `#page-knowledge-graph`). Tiny family-coloured dots, dagre BT layout, tap highlights the closed neighbourhood. Built lazily via `window.deltaInitConceptGraph()` (Cytoscape can't size a `display:none` container). Loads `graph-viz.json` by relative fetch.
- **`graph-audit.html`** — standalone, self-contained **content & structure review** page (justinmath-style). Two-pane: left = clicked skill's detail (label, family/topic/tier, direct prerequisites, unlocks, chain depth — all clickable); right = labeled *bubbles* in a bottom-up prerequisite tree, click lights up the full prerequisite chain in gold. Loads the same `graph-viz.json`. Runs with **no auth/backend** so it can be previewed over a plain static server. Intended as the design prototype for replacing `graph-viz.js`'s dots-only view in the tab.
- **`atom_readiness.js`**, **`prereq_subtopics.js`** — client-side helpers (readiness scoring / prereq subtopic lookup) keyed by atom id.
- **`iter5_v2.js`** — large iter-5 v2 atom/prereq dataset.

## Data & External Dependencies

- **Cytoscape.js 3.30** + **dagre 0.8** + **cytoscape-dagre 2.5**, loaded from jsdelivr CDN (already trusted by the app). `graph-audit.html` loads them itself; `graph-viz.js` relies on the tags in `index.html`.
- `graph-viz.json` is the single shared data source for both viz surfaces.

## How It Works (Flow)

1. Pipeline exports `graph-viz.json` from the derived concept graph.
2. **Tab view:** app opens Knowledge Graph tab → `deltaInitConceptGraph()` → `graph-viz.js` fetches the JSON, builds a dagre-BT Cytoscape graph, colours by `family`, draws `enc:false` edges red / `enc:true` dashed.
3. **Audit view:** `graph-audit.html` fetches the same JSON, builds `parentsOf`/`childrenOf` from `enc:false` edges only, renders labeled bubbles, and on click BFS-walks `parentsOf` to highlight the full prerequisite chain + populate the left detail pane.

## Invariants & Constraints

- **Edge direction is load-bearing:** `source` is the prerequisite, `target` is the dependent. `rankDir: "BT"` places prerequisites at the bottom. Do not flip without updating both viz files.
- **Only `enc:false` edges form the prerequisite tree / ancestor chain.** `enc:true` edges are display-only (dashed, toggleable) and must be excluded from ancestor/readiness walks.
- `graph-viz.json` is **generated** — never hand-edit; regenerate via the exporter or downstream diffs get clobbered.
- Ancestor walks must be cycle-safe (use a visited set). Current data is a DAG (deepest chain 17) but don't assume acyclicity without the guard.
- Atom ids here are the concept-graph ids; they do **not** map 1:1 to `lessons/` (`kp-*`) or the question bank keys.

## Extension Points

- To change the tab's look, edit `graph-viz.js` (or port `graph-audit.html` into it once its style is approved).
- New per-node fields: add them in the exporter → they appear in `graph-viz.json` → surface in the `data(...)` mappers / info panel.
- To show real per-skill content (drill/lesson) in the audit pane, first establish an atom-id → question/lesson mapping (none exists today).
