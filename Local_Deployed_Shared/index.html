How Delta Drills works

Intro tutorials are everywhere. The hard part is the jump from following along to writing the code yourself — the tensor manipulations, the convolutions, the building blocks of modern ML research. Delta Drills is a practice engine for exactly that gap.

Under the hood is an expert system that emulates the decisions of an expert tutor: at any given moment, what is the single best thing for you to work on? It answers that by combining the pieces of technology below — heavily supported when a topic is new, stripped bare once you've got it.

That blueprint isn't speculative. It's the approach Math Academy uses to move students through years of mathematics at well-documented speed. Delta Drills rebuilds that proven engine for machine learning — and uses AI to generate the curriculum map and the thousands of practice problems that fill it.

The idea

You move on when you've got it — not when the clock says so

Most courses march everyone through the same sequence at the same pace. Delta Drills is built around mastery learning instead: you keep working a skill until the evidence says you've actually learned it, foundations first — so you never hit an advanced problem missing a piece you were quietly never taught.

The engine that makes this work combines a handful of pieces — the same core technology behind a system like Math Academy, rebuilt for machine learning. Each is described below: the knowledge graph, the student model, the prerequisite gating that decides what you're ready for, the task-selection step that picks your next problem, and a support layer that decides how much help it comes with.

1 · The knowledge graph

A map of what depends on what

The knowledge graph stores what an expert tutor would know about how machine learning fits together. What skills are there? Which ones must you understand before you can learn a given topic? When you struggle with a problem, which earlier skills are the likely culprits? Which harder skills quietly contain which simpler ones? The answers live in the graph — a few hundred individual skills ("atoms") and the links between them, assembled by an AI pipeline that reads real ML teaching material and cross-checks the structure across several independent sources, so it reflects how the field is actually taught rather than one author's guess.

Two kinds of link do most of the work. Prerequisite links say one skill must come before another — reshaping with einops before building an attention head, understanding a convolution before assembling a ResNet. Encompassing links say a harder skill quietly contains a simpler one. The first kind decides what unlocks; the second lets credit flow back down the graph.

~210 skill atoms across the curriculum
~480 coding problems, auto-graded
~1,300 hands-on drills pulled from research workflows

2 · The student model

A running estimate of what you actually know

The student model takes your answers, overlays them on the knowledge graph, and works out which skills you know and how well — your skill profile. Each problem you submit nudges the estimate for the skills it touches, up when you're right and gently down when you slip, using a well-established method called Bayesian Knowledge Tracing. It expects the obvious noise: a lucky guess and an unlucky typo aren't taken as the whole story.

To decide when something needs review, the student model uses spaced repetition. Confidence in a skill fades over time along a forgetting curve; once it has faded far enough, the skill resurfaces for review — so practice is spread out over time, and the shakier a skill is, the sooner it comes back. Review is driven by how much you're likely to have forgotten, not a fixed calendar.

Crucially, repetitions trickle down the graph. Because it knows which skills are contained in which, getting a hard, composite problem right passes implicit credit to the simpler skills folded inside it — so advanced work refreshes its own foundations, and you're never made to re-grind something you've already demonstrated.

3 · Knowing what you're ready for

What you've already got — and what's missing underneath

An expert tutor doesn't just track what you know; they find the boundary — what you've already learned, and which foundations are missing and holding you back. Delta Drills reads that boundary straight off the graph. A skill counts as ready only once the skills beneath it are solid; until then it stays locked, and the missing foundation is what gets surfaced first. A short calibration at the very start (your first few problems, at fixed difficulty) gives the engine an initial read before it begins adapting to you.

This is the same job a diagnostic exam does — identifying what you already know and where your foundational gaps are — handled continuously through prerequisite gating rather than as one upfront test. (Math Academy front-loads it with an adaptive diagnostic that pinpoints your frontier in a handful of questions; a dedicated diagnostic is a natural next step here.)

4 · The task-selection algorithm

Picking the one thing that moves the needle most

The task-selection step takes your skill profile and picks the learning task that will move the needle most: what should you learn next, and what needs review? It is always trying to maximize how much learning happens per minute you spend. In practice that means finding your weakest skill that you're actually ready for and serving a problem there, at a difficulty tuned to your current mastery so it stretches you without stalling you.

A topic unlocks the moment the skills beneath it are solid — no busywork holding you at a level you've already cleared — and because review rides on the same selection, a single well-chosen problem can refresh several rusty skills at once through the graph.

5 · The support layer

The training wheels come off as you improve

Showing a beginner a fully worked example is one of the most effective things you can do. Showing that same worked example to someone who's already fluent just slows them down — a well-documented effect in the learning-science literature (the expertise reversal effect). So Delta Drills doesn't hand everyone the same problem. Each drill exists at three levels of support, and which one you get depends on how you're doing:

New to it

Worked

The full solution, laid out and explained. You read the reasoning and run it.

x = rearrange( img, "h w c -> c h w" ) # ✓ shown
Getting there

Faded

Most of the scaffold is there; you fill the blanks that carry the real idea.

x = rearrange( img, "____" ) # you fill this
Fluent

Full

A blank problem and a hint if you want it. You write the whole thing.

# goal: HWC -> CHW # write it yourself

support fades as mastery rises →

The substance

You write real code, on real research patterns

Reconstructed from actual workflows

The drills aren't toy puzzles. They're broken out of the kinds of exercises researchers use to learn the field — the tensor work, the model internals — so the skill you build is the one the work actually demands.

Graded on what your code does

You write Python — numpy, einops, PyTorch — and submit. The engine runs it and checks the result, so feedback is about whether your solution behaves correctly, not whether it matched a template.

Help when you're stuck

Every problem can surface a hint or a fully worked solution on demand — there when you need it, out of the way when you don't.

Built for different starting points

Because support is tiered and practice is weakest-first, the same library of problems serves someone seeing a concept for the first time and someone sharpening skills they mostly have.

Where it's at. Delta Drills is an early, working build focused on the foundational ML skills behind modern research. Every part of the engine described above is live — the knowledge graph, the Bayesian student model with spaced-repetition review and trickle-down credit, prerequisite gating, weakest-first task selection, and the fading-scaffold support layer. The proven part is the pedagogy; the new part is using AI to generate the curriculum and problems that fill it — so the banks keep growing.
