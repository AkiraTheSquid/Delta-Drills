How Delta Drills works

Intro tutorials are everywhere. The hard part is the jump from following along to writing the code yourself: the tensor manipulations, the convolutions, the parts of modern ML research you have to be able to type out. Delta Drills is a practice engine for that gap.

Underneath it is an expert system answering the question a good tutor answers all day. Right now, what is the single best thing for you to work on? The pieces described below are how it answers, with heavy support when a topic is new and none once you have it.

The design is borrowed. Math Academy has used it for years to move students through mathematics at speeds they document publicly. Delta Drills rebuilds that engine for machine learning, and uses AI to write the curriculum map and the thousands of problems that fill it.

The idea

You move on when you've got it, not when the clock says so

Most courses march everyone through the same sequence at the same pace. Delta Drills is built around mastery learning instead. You keep working a skill until the evidence says you have learned it, foundations first, so you never hit an advanced problem missing a piece nobody ever taught you.

1 · The knowledge graph

A map of what depends on what

The graph holds what a tutor knows about how machine learning fits together. What skills are there? Which ones do you need before you can learn a given topic? When you get stuck, which earlier skill is the likely culprit? It is a few hundred individual skills ("atoms") and the links between them, built by an AI pipeline that reads real ML teaching material and cross-checks the structure against several independent sources, so the shape comes from how the field is taught rather than from one author's guess.

Two kinds of link do most of the work. Prerequisite links say one skill comes before another: reshaping with einops before building an attention head, convolutions before a ResNet. Encompassing links say a harder skill quietly contains a simpler one. The first decides what unlocks. The second lets credit flow back down the graph.

~210 skill atoms across the curriculum
448 coding problems, auto-graded
~1,300 hands-on drills pulled from research workflows

2 · The student model

A running estimate of what you actually know

The student model lays your answers over the graph and works out which skills you have and how well, your skill profile. Each problem you submit moves the estimate for the skills it touches, up when you are right and gently down when you slip, by a long-established method called Bayesian Knowledge Tracing. It expects noise, so one lucky guess or one unlucky typo is never the whole story.

Review is scheduled by spaced repetition. Confidence in a skill decays along a forgetting curve, and once it has decayed far enough the skill comes back around. The shakier the skill, the sooner it returns. What drives it is how much you are likely to have forgotten rather than a fixed calendar.

Those repetitions trickle down the graph. Because the model knows which skills sit inside which, getting a hard composite problem right passes credit to the simpler skills folded into it. Advanced work refreshes its own foundations, and you never re-grind something you have already shown you can do.

3 · Knowing what you're ready for

What you've already got, and what's missing underneath

A tutor tracks what you know and also finds the boundary: what you have learned, and which missing foundation is holding you back. Delta Drills reads that boundary off the graph. A skill counts as ready only once the skills beneath it are solid. Until then it stays locked and the missing foundation is what you get served first. A short calibration at the start, your first few problems at fixed difficulty, gives the engine something to work from before it starts adapting to you.

That is the job a diagnostic exam does, handled continuously through prerequisite gating instead of as one test up front. (Math Academy front-loads it with an adaptive diagnostic that finds your frontier in a handful of questions. A dedicated diagnostic is a natural next step here.)

4 · The task-selection algorithm

Picking the one problem worth your next ten minutes

Task selection reads your skill profile and picks what to serve, new material or review, aiming for the most learning per minute you spend. In practice it finds your weakest skill that you're actually ready for and serves a problem there, at a difficulty set by your current mastery so it stretches you without stalling you.

A topic unlocks the moment the skills beneath it are solid, so nothing holds you at a level you have already cleared. Review runs through the same selection, which is why one well-chosen problem can refresh several rusty skills at once.

5 · The support layer

The training wheels come off as you improve

Showing a beginner a fully worked example is one of the most effective things you can do. Showing that same example to someone who is already fluent slows them down, an effect the learning-science literature documents as the expertise reversal effect. So the same drill exists at three levels of support, and which one you get depends on how you have been doing:

New to it

Worked

The full solution, laid out and explained. You read the reasoning and run it.

x = rearrange( img, "h w c -> c h w" ) # ✓ shown
Getting there

Faded

Most of the scaffold is there; you fill the blanks that carry the real idea.

x = rearrange( img, "____" ) # you fill this
Fluent

Full

A blank problem and a hint if you want it. You write the whole thing.

# goal: HWC -> CHW # write it yourself

support fades as mastery rises →

The substance

You write real code, on real research patterns

Reconstructed from actual workflows

The drills come out of the exercises researchers use to learn the field, the tensor work and the model internals, so the skill you build is the one the work demands.

Graded on what your code does

You write Python (torch, einops) and submit. The engine runs it and checks the result, so the feedback is about how your solution behaves, never about how closely it matched a template.

Help when you're stuck

Every problem can show a hint or a full worked solution on demand, and stays quiet until you ask.

Built for different starting points

Support is tiered and practice is weakest-first, so the same library serves someone meeting a concept for the first time and someone sharpening skills they mostly have.

What this app is for

ARENA Delta Drills is built for one curriculum: ARENA.

ARENA takes you from PyTorch fundamentals to original AI-safety research, and it assumes you can already write the code — the tensor manipulation, the einops, the training loops. This app is the practice engine for exactly that assumption. It drills the mechanics behind the chapters below, tracks which ones you have, and sends you to the real ARENA exercise once you're ready for it. It is not a replacement for the course; it is the reps the course expects you to have already done.

You're on the main edition — drills are solved in the app's own code editor. You're on the Colab edition — drills open as Colab notebooks, and the app tutors alongside them.
