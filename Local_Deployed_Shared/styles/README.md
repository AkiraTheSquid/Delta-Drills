# styles

## Purpose
- Global CSS for the Delta Drills root UI. Owns the visual layer: color tokens, layout primitives, reusable component styles, and per-feature stylesheets that index.html links directly.

## Owns
- **All three themes.** `variables.css` defines the same token vocabulary three times — `blue` (the original palette, and the default), `dark` (Colab-style neutral greys) and `light` — keyed on `:root[data-theme="…"]`. Which one is live is decided by `../theme.js`, not by anything in here.
- Cross-cutting layout, base, component, and responsive rules.
- Per-feature stylesheets co-located here (arena, stats, courses) that style a single tab/page.

## Does NOT own
- Which theme is active, how it is stored, or the Account-page picker — that is `../theme.js` (it stamps `<html data-theme>` before first paint and renders the radio group into `#account-theme-options`). This folder only says what each theme *looks* like.
- Practice tab styling — lives at `Local_Deployed_Shared/practice.css` and `Local_Deployed_Shared/practice/bars.css` (loaded directly by index.html).
- DOM structure, behavior, or data — those are owned by the JS in the parent folder and feature subfolders.
- Backend / Python concerns.

## Key Files
- `variables.css`: design tokens (colors), three times over — one block per theme plus a theme-independent tail. Loaded first so every other stylesheet can reference them. Two things to know before editing it:
  - **Parity is enforced.** Every theme block must declare exactly the same token names; `watch.py` fails the folder if one does not. A token defined in only two of three themes does not fall back to something sensible — the declarations that use it drop, which is how you ship white-on-white.
  - **Two ladders, not a pile of alphas.** Raised film (chips, hairlines, hovers) is `rgb(var(--tint-rgb) / calc(α * var(--tint-k)))`; recessed wells (code blocks, inset fields) are `rgb(var(--well-rgb) / calc(α * var(--well-k)))`. The dark themes tint with white over black; light flips the ink to slate (`--tint-rgb: 15 23 42`) *and* scales the whole ladder down (`--tint-k`, `--well-k`), so a new translucent surface inherits a sane light-mode value without anyone restating its alpha. `--wash-k` does the same job for coloured washes (banner gradients), which want to be much weaker on white.
- `base.css`: resets and global element defaults.
- `scrollbars.css`: **base layer, not a feature.** `color-scheme` keyed per theme (`dark` by default, `light` under `[data-theme="light"]`) plus the `::-webkit-scrollbar` skin every scroller in the app inherits. Deliberately unscoped — a scrollbar is chrome, not content, and nothing here wants the platform's white one. The two mechanisms are not redundant: Chrome ignores `color-scheme` for any scroller a `::-webkit-scrollbar` rule matches, and `color-scheme` reaches bars the skin cannot. Must be linked before `layout.css`; `watch.py` asserts it.
- `layout.css`: page shell, container, tabs nav layout.
- `nav-drawer.css`: the hamburger menu the tab strip moves into below 900px — the toggle, the off-canvas drawer, its scrim, and `.tabs`/`.tab` restyled as a vertical list. Every rule is scoped under `body.nav-drawer-mode`, a class `../nav-drawer.js` adds, so the topbar strip is untouched at every other width (this file does not violate the "no global selector over the tabs nav" rule below). The `.tabs` grid is two columns so each tab and its ⓘ share a row. Behaviour, and the DOM move itself, live in `../nav-drawer.js`.
- `components.css`: reusable atoms (buttons, inputs, cards, hints).
- `responsive.css`: viewport-based overrides; loaded last so its rules win.
- `arena.css`: ARENA tab styling.
- `infotips.css`: the ⓘ system — the dot (`.dd-info`, plus its topbar variant `.dd-info.tab-info`) and the single reused explanation panel (`.dd-infopop`). Behaviour and copy live in `../infotips.js` and `../infotips-registry.js`.
- `how-it-works.css`: **legacy filename**, in the same way `stats.css` is. The How It Works page it was written for was deleted 2026-08-22; its `.hiw-*` type scale was inherited by **Why this app exists** (`#page-why-this-app`), which is now the landing page, and the three `#page-how-it-works` selectors were repointed there. ## How It Works (Flow)
1. `index.html` loads stylesheets in this order: variables → base → scrollbars → layout → components → how-it-works → stats → arena → courses/page → courses/forkgate → courses/detail → courses/modal → courses/responsive → infotips → nav-drawer → responsive (then practice CSS separately).
2. The order matters — `responsive.css` and feature stylesheets must come after the tokens and base layer so their selectors override correctly.
3. Each feature CSS file scopes its rules with a feature-prefixed class (`.arena-*`, `.stats-*`, `.courses-*`, `.course-card-*`) to avoid collisions. `.stats-*` is the one prefix that no longer maps to a tab — it survives as the shared progress-bar vocabulary.

## Invariants & Constraints
- New feature stylesheets must reference colors via CSS variables from `variables.css` — never hardcode hex values. Watch enforces this on token-first files (currently every `courses/*.css` fragment), and separately bans **light-on-dark literals** — every spelling of white, including `#fff8`/`#ffffff80` and the space-separated `rgb(255 255 255 / α)` — across every stylesheet in this folder and in `../practice/` and `../targeted-practice/`. That last form is the one to watch: the tint ladder is written `rgb(var(--tint-rgb) / …)`, so it is the syntax an author now reaches for by imitation. That second check is the light-mode guard: a hardcoded white is invisible on a white page and nothing else will catch it. Two mechanical exemptions exist and are the only ones — a rule whose selector contains `[data-theme-preview=` (the Account swatches are pictures of themes the viewer is *not* in, so they must be literal), and any line marked `/* graph-legend */` (those must match node colours Cytoscape paints from JS).
- **Every theme block in `variables.css` declares the same tokens.** Adding a token means adding it three times. `watch.py` asserts parity and will fail the folder otherwise.
- **The Account swatches are a hand-copy, and `watch.py` keeps them honest.** Every hex in a `[data-theme-preview="X"]` rule must still exist somewhere in theme `X`'s block. The check is loose about which role a colour plays (the blue miniature draws its card with `--surface` because that reads better at 62px) and strict about the colour being real — so changing a palette fails the folder rather than leaving the picker advertising a colour the theme dropped.
- `variables.css` must be the first stylesheet linked in `index.html`, and `responsive.css` must be linked after `components.css` and after every feature stylesheet so its overrides win.
- Feature class prefixes must stay unique per tab (e.g. `.courses-*` for the Courses page, `.arena-*` for ARENA) to keep concerns isolated.
- Do not reintroduce a global selector that overrides the tabs nav layout — that lives in `layout.css` and is fragile.

## Extension Points
- New tab/page styling: add `<feature>.css` here, link it in `index.html` after `components.css` and before `responsive.css`, prefix all selectors with `.<feature>-` or a feature-scoped wrapper class.
- New design tokens: add to `variables.css` only, **in all three theme blocks**. Never define ad-hoc color or spacing constants in a feature file.
- New translucent surface: reach for the tint or well ladder rather than a literal `rgba()`. `rgb(var(--tint-rgb) / calc(0.06 * var(--tint-k)))` is correct in all three themes; `rgba(255,255,255,0.06)` is correct in two and invisible in the third.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **Hardcoded colors drift from the token palette** — `ACTIVE`
  - When it happens: a feature stylesheet inlines `#abc123` instead of `var(--accent)` because the author was iterating quickly.
  - Symptom: theme/palette changes in `variables.css` skip those rules and the UI looks inconsistent.
  - Root cause: copy-paste from prototypes that predate the variable system.
  - Prevention/fix: always reach for an existing `--*` token; add a new one to `variables.css` if none fits.
  - Status: `ACTIVE`.

- **A hardcoded white goes unnoticed until someone switches to the light theme** — `GUARDED`
  - When it happens: a rule sets `color: #fff` or `background: rgba(255,255,255,0.06)` because the author only ever looked at the dark palettes, where both read fine.
  - Symptom: white text on a white card in the light theme — legible nowhere, and invisible in review because the reviewer is usually in the default theme too.
  - Root cause: two of the three themes are dark, so the failure mode is silent in the two places anyone looks by default.
  - Prevention/fix: `watch.py` now greps every stylesheet in this folder, `../practice/` and `../targeted-practice/` for light-on-dark literals and fails on any hit outside the two documented exemptions. If a literal is genuinely correct, it needs one of those two markers, not an edit to the regex.
  - Status: `GUARDED`.

- **Auditing contrast in a live page reads mid-transition colours** — `ACTIVE`
  - When it happens: you flip `data-theme` from the console and immediately sample `getComputedStyle().color` to check ratios.
  - Symptom: catastrophic phantom failures — `.tab.active` reporting white-on-white at ratio 1.0, `.dd-info` at 2.4 — that vanish if you wait a second. Acting on them means "fixing" bugs that do not exist.
  - Root cause: `.tab` and `.dd-info` carry `transition: color 0.15s`, so a synchronous sample catches the interpolated value, not the settled one.
  - Prevention/fix: inject `*, *::before, *::after { transition: none !important; animation: none !important; }` before sampling anything. This flipped one audit from "7 light-theme failures" to zero.
  - Status: `ACTIVE`.
