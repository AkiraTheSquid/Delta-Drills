# content_review

## Purpose
- Written output of content reviews against `scripts/CONTENT_RUBRIC.md`: what a model reviewer (GPT-6 Astra via `codex exec`, Claude Fable in-session) found wrong with drill prompts and lesson pages, so the fixes can be made and re-checked.

## Owns
- One report per review run, named `YYYYMMDD-<scope>-<reviewer>.md`, plus the `YYYYMMDD-<scope>-task.md` file both reviewers were given.
- The reconciliation notes (agreed / fable-only / astra-only) for a run, when written.

## Does NOT own
- The rubric itself (`scripts/CONTENT_RUBRIC.md`), the mechanical rules (`scripts/lesson_quality.py`), or the runner (`scripts/content_critic.py`).
- The content: drills live in `This-Directory-Only/questions_full.json`, pages in `Local_Deployed_Shared/lessons/`.

## Key Files
- `20260907-einops-astra.md`: GPT-6 Astra (xhigh) agentic review of q847–940 + 12 einops KP pages.
- `20260907-einops-fable.md`: Fable's in-session review of the same scope.
- `20260907-einops-task.md`: the task both reviewers were given (regenerated by `content_critic.py --dry-run`).
- `20260907-0904-einops-00.*`: empty output of the retired chunked `content_critic.py` (all calls errored before spending tokens); kept as a record.

## Data & External Dependencies
- Reads nothing at runtime; reports are plain markdown written by a reviewer. `content_critic.py` writes the task file and launches the single Astra run (`codex exec`, read-only, effort pinned).

## How It Works (Flow)
1. Reviewer reads the rubric, the KP pages and the drill rows with its own tools.
2. Reviewer writes one report here; findings cite a rubric CODE, severity, exact quote, and a rewrite.
3. Author reconciles the reports, verifies single-reviewer findings against the data, then fixes the content and re-runs `audit_ladder_pairing.py --strict`.

## Invariants & Constraints
- At most TWO model processes per review (one per model), each agentic over the whole scope — never fan out per chunk (Seth, 2026-09-07).
- Reviewers never edit content. A finding raised by one reviewer is verified before it is acted on.
- Raw reports may be large; do not paste them into chat, summarise.

## Extension Points
- New scope: run the reviewer with a task file naming the rubric, the pages and the id range; drop the report here with the naming pattern above.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **Fan-out cost** — `RESOLVED`
  - When it happens: `content_critic.py` chunked the scope and launched a process per chunk (24 at once).
  - Symptom: Seth: "did you run 24 calls at once? holy shit".
  - Root cause: chunking + ThreadPoolExecutor per chunk.
  - Prevention/fix: one agentic run per model, reviewer reads files itself.
  - Status: `RESOLVED` 2026-09-07 — `content_critic.py` rewritten as a one-run launcher (task file + one `codex exec`); Fable reviews in-session.
