# concept-graph

Atoms, composites, and (eventually) a prereq DAG over the ARENA 5.0 curriculum, used to drive Delta Drills's "stuck → drill this concept" recommender.

## Layout

```
concept-graph/
├── vocab/
│   ├── atoms.json              # canonical atom vocabulary (append-only)
│   ├── concept_edges.json      # SOURCE: semantic relations between atoms
│   ├── prereq_manual.json      # SOURCE: curriculum sequencing decisions
│   └── prereqs.json            # GENERATED: DAG of teaching order
├── exercises/<id>.json         # one file per tagged ARENA exercise
├── scripts/
│   ├── validate.py             # atom-ref check across exercises
│   ├── validate_concept.py     # schema + per-kind DAG check on the two source files
│   ├── derive_prereqs.py       # regenerate prereqs.json from sources
│   ├── validate_graph.py       # DAG check on generated prereqs.json
│   └── export_graphml.py       # emit two yEd-readable .graphml files
├── concept-graph.graphml       # GENERATED: visualize concept_edges (semantic)
├── prereq-graph.graphml        # GENERATED: visualize prereqs (teaching order)
└── README.md
```

## Two-graph model

- **Concept graph** (`concept_edges.json`): hand-authored semantic relations. Edge kinds: `is-a`, `refines`, `uses`, `part-of`, `alternative-to`. Source of truth.
- **Prereq graph** (`prereqs.json`): DAG of teaching order, generated by `derive_prereqs.py`. Derivation rules:
  - `is-a / refines / uses A→B` ⇒ prereq `B → A` (foundation before built-on)
  - `part-of A→B` ⇒ prereq `B → A` (whole before part; ARENA teaches top-down)
  - `alternative-to` ⇒ no prereq induced (sequencing goes in `prereq_manual.json`)
- **Manual overrides** (`prereq_manual.json`): pure curriculum sequencing decisions that don't fall out of the semantics.

To edit the graph: change `concept_edges.json` or `prereq_manual.json` and run `python scripts/derive_prereqs.py`. Never edit `prereqs.json` directly.

## Workflow

1. **Tag a new exercise.** Read the notebook. Write `exercises/<arena_id>.json` with:
   ```json
   {
     "exercise_id": "0_2_4",
     "atoms": [{"id": "atom-id", "role": "core|incidental", "evidence": "..."}, ...],
     "atoms_in_seed_but_not_actually_present": [...],
     "tagged_by": "...", "tagged_at": "YYYY-MM-DD"
   }
   ```
2. **Run the validator:** `python3 concept-graph/scripts/validate.py`. It lists any atom ids referenced by exercises but missing from the vocab.
3. **Review proposed atoms.** Either add them to `vocab/atoms.json` (real atoms) or rename the reference in the exercise file (typo / duplicate of existing).


## yEd visual review

1. Run `python concept-graph/scripts/export_graphml.py` → writes both `concept-graph.graphml` and `prereq-graph.graphml`.
2. Open whichever you want to inspect in yEd.
3. Tools → Fit Node to Label.
4. Layout → Hierarchical (top-down). Cycles appear as red feedback arcs (currently DAG-clean for prereqs).
5. Edge style legend:
   - `prereq` solid black; `uses` solid black; `is-a` dashed green; `refines` dashed blue; `part-of` dash-dot purple; `alternative-to` dotted pink.
   - Line weight 2px = `accepted`, 1px = `proposed`.
6. Node color = deterministic hash of the atom's `domain`.

## What's deliberately NOT here yet

- Hooks (PreToolUse schema check, PostToolUse dedup check) — `watch.py` covers most of this on every edit.
- Transfer score calculation — needs ≥2 exercises tagged per atom; trivial to compute once they are.
- Recommender integration with the backend's EWMA (`This-Directory-Only/backend/app/adaptive.py`) — downstream of the graph existing.
