# This-Directory-Only

## Purpose
Local-only assets that are deliberately excluded from the deployed bundle — the FastAPI backend, AI quality-fix pipeline, raw question CSVs, ingestion scripts, supabase config, and developer tooling. Contrast with `../Local_Deployed_Shared/`, which IS bundled into the deploy worktree.

## Owns
- The FastAPI backend (`backend/`) that serves `/api/practice/*` endpoints in dev and on Fly.io.
- AI quality-fix pipeline runtime artifacts under `chatgpt/` (overrides, deleted/broken IDs, prompt requests/responses).
- Source-of-truth question banks: `csv files of problems/*.csv` (numpy, einsum, einops).
- Ingestion / export scripts (`scripts/`): `build_function_bank.py`, `validate_function_bank.py`, `export_questions_json.py`, `extract_arena_prereqs.py`.
- Mathpix-processor pipeline for converting PDF chapters → markdown.
- Supabase migrations and storage config.
- Local dev server entry-point: `serve.py` (frontend at port 5174, backed by NoCacheHandler).

## Does NOT own
- Frontend code, UI assets, or anything the user sees in the browser — lives in `../Local_Deployed_Shared/`.
- Production secrets — those are in Fly.io / Vercel env, not in this tree (dev `.env` files are local only).
- ARENA upstream content — sourced from `../Local_Deployed_Shared/ARENA_*-main/`, never edited here.

## Key Files
- `serve.py`: tiny http.server wrapper that serves `Local_Deployed_Shared/` at port 5174 with `Cache-Control: no-store`. Started by the `delta_drills_local` alias.
- `backend/`: FastAPI app. See its own README for endpoints. Boots from CSV via `app.questions.load_questions()`, applies AI overrides on top.
- `chatgpt/`: AI pipeline runtime dir. Contains `function_mode_overrides.jsonl`, `einops_prompt_rewrite_overrides.jsonl`, `function_mode_validation_failures.jsonl`, `function_mode_broken_ids.json`, `function_mode_deleted_ids.json`, plus `api_key.txt`. **Don't commit api_key.txt.** Path is configurable via `DELTA_CHATGPT_RUNTIME_DIR` env var.
- `csv files of problems/`: raw question banks. `Export of numpy problems with outputs.csv`, `einsum_problems.csv`, `einops_problems.csv`.
- `QUESTION_PIPELINE_AND_PEDAGOGY_ARCHITECTURE.md`: explains both the older upstream `pdf_2_problem/Problem Generator` pipeline and the current Delta Drills content/runtime system, including how the schemas and pedagogy connect.
- `scripts/build_function_bank.py`: orchestrator — runs export → validate → AI repair (3 rounds max) → re-export.
- `scripts/export_questions_json.py`: CSV → `questions_full.json` (validator input) and the public `Local_Deployed_Shared/questions{,_structured}.json` (frontend).
- `scripts/validate_function_bank.py`: per-question harness checks (starter parses, expected_expr resolves, synthesized solution executes).
- `questions_full.json`: validator's working copy of the bank (with overrides applied). Regenerated by `export_questions_json.py`.
- `Dockerfile`, `fly.toml`: deploy config for Fly.io backend (`delta-drills-backend`).

## Data & External Dependencies
- **Source-of-truth question CSVs** consumed by both the backend (live, in-memory) and the export script (offline, JSON).
- **OpenAI API** via `chatgpt/api_key.txt` for the AI repair pipeline.
- **Supabase** for user state, attempts, streaks (project ref `qaxtcaoydbpigomnfjpl`).
- **Postgres** via `backend/schema.sql` (local dev) — supabase mirrors the schema in prod.
- **Fly.io** runs the backend at `delta-drills-backend.fly.dev` from `Dockerfile` + `fly.toml`.

## How It Works (Flow)
1. `delta_drills_local` (alias) starts uvicorn on port 8000 (backend) + `serve.py` on port 5174 (frontend).
2. Backend boot → `app.questions.load_questions()` reads CSVs, applies overrides from `chatgpt/`, builds in-memory store.
3. Frontend hits `/api/practice/next-question` — backend returns a question from the merged store.
4. AI quality fix (manual): `python3 scripts/build_function_bank.py` runs export → validate → if any failures, generate repair requests → call ChatGPT batch → write `function_mode_overrides.jsonl` → repeat up to 3 rounds.
5. Einops prompt rewrite (manual): `python3 ../Local_Deployed_Shared/rewrite_einops_prompts.py` rewrites pattern-leaking prompts → writes `einops_prompt_rewrite_overrides.jsonl` → backend merges on next boot.
6. Browser dev flow: `delta_drills_dev` starts Delta Drills, opens Chrome with a dedicated remote-debugging port, and runs `This-Directory-Only/scripts/watch_delta_drills_dev.py` in the background. That watcher closes any non-Delta-Drills tab it sees on the debug port, so a stale profile cannot leak Delta Note or any other app into the MCP session.

## Invariants & Constraints
- Anything in this folder is **NOT bundled** into the deploy worktree — must not be referenced by frontend code paths that ship.
- The CSVs are the source of truth for question content. Don't edit `questions_full.json` directly; regenerate via `export_questions_json.py`.
- The backend's `_load_function_overrides()` is the merge point — both `function_mode_overrides.jsonl` and `einops_prompt_rewrite_overrides.jsonl` must be honored. Adding a third overlay file means updating the merge.
- `api_key.txt` and `.env` files must never be committed.
- Question IDs are CSV-row-position-derived; reordering rows breaks override stability. Append, don't reorder.
- `delta_drills_dev` must stay isolated from other app profiles. It uses a dedicated Chrome profile plus `watch_delta_drills_dev.py` to keep the remote-debug session scoped to `http://localhost:5174`.

## Extension Points
- **Add a new question topic**: drop a CSV in `csv files of problems/`, register it in `backend/app/questions.py:load_questions()` and `scripts/export_questions_json.py:CSV_SOURCES`, mind the ID range to avoid collisions.
- **Add a new AI repair stage**: write a new system-prompt file in `Local_Deployed_Shared/`, write a request builder in `Local_Deployed_Shared/`, write outputs to a new JSONL in `chatgpt/`, extend `_load_function_overrides()` to merge it.
- **Add a new backend endpoint**: see `backend/README.md` and `backend/app/practice/` patterns.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **Backend bypasses AI overrides** — `RESOLVED`
  - When it happens: backend mode (admin/localhost) served questions directly from CSV, ignoring `function_mode_overrides.jsonl`.
  - Symptom: AI-repaired starters never reached the user; pre-existing bugs reappeared.
  - Root cause: `app.questions.load_questions()` re-derived starter_code from CSV without consulting overrides.
  - Prevention/fix: `_load_function_overrides()` and `_load_id_set()` are now called in `load_questions()`, and `_load_csv_into()` applies them. **Don't remove this without also routing the overrides somewhere else.**
  - Status: RESOLVED (2026-04-28).

- **Pattern leakage in einops prompts** — `RESOLVED`
  - When it happens: 45 of 92 einops CSV rows had the einops arrow pattern (`b c h w -> b c w h`) embedded in the prompt itself.
  - Symptom: questions trivially solvable by syntax-wrapping the pattern from the prompt.
  - Root cause: original CSV authored with patterns inline as a shorthand for the author, not for the student.
  - Prevention/fix: `Local_Deployed_Shared/rewrite_einops_prompts.py` rewrites prompts in plain English; output goes to `chatgpt/einops_prompt_rewrite_overrides.jsonl`. Re-run if any new einops CSV rows are added with arrow patterns.
  - Status: RESOLVED (2026-04-28).

- **Validator only checks runtime, not pedagogy** — `ACTIVE`
  - When it happens: `validate_function_bank.py` confirms harness executes, but doesn't compare `answer_code` against `starter_code` to detect leakage.
  - Symptom: leaky starters pass validation; broken paste-flow not caught.
  - Root cause: validator was scoped to runtime correctness only.
  - Prevention/fix: pending — add "no answer leakage" and "answer is paste-compatible" checks. Until then, manual audit any new CSV rows.
  - Status: ACTIVE.
